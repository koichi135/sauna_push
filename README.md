# サウナ・コインプッシャー

サウナ室を舞台にしたエンドレス型コインプッシャー。コイン＝サウナストーン。
落ちたストーンはストーブに供給され、室温が上がる。プレイヤーは「熱すぎず、ぬるすぎない」
適温を維持しながら *ととのいゲージ* を溜め、水風呂→外気浴（フィーバー）でスコアを稼ぐ。
山が崩れてまとまって落ちれば**コンボ**、10 連鎖で**大玉ストーン**。
セットを重ねるほどサウナは熱くなり、外気浴で回復した体力を次のセットに賭ける。

モバイルブラウザ（縦持ち）向けの 3D ゲーム。全操作シングルタップ。

## 起動

```bash
npm install
npm run dev        # 開発サーバ
npm run build      # 型チェック + 本番ビルド (dist/)
npm run preview    # ビルド結果の確認
npm run typecheck  # 型チェックのみ
```

`?debug=1` を付けて開くと、右上に調整パネルが出る（既定は畳んだ状態。見出しをタップで開閉）。
仕様書 12 章の必須要件で、全バランス値のスライダーと、温度・水風呂・アイテムなどの
強制発火ボタンが入っている。スライダーは `BALANCE` を実行時に書き換えるので、
実機で触りながらそのまま詰められる。

## 公開（GitHub Pages）

`main` への push で `.github/workflows/deploy.yml` が走り、GitHub Pages へ自動デプロイされる。
Actions タブから手動実行（workflow_dispatch）もできる。

公開先: `https://koichi135.github.io/sauna_push/`

`npm run build` は `tsc --noEmit` を含むので、型エラーがあればデプロイ前に落ちる。
Vite の `base` は `'./'`（相対）にしてあり、リポジトリ名のサブパス配下でもそのまま動く。

初回のみ、リポジトリの **Settings > Pages > Source** が **GitHub Actions** になっている
必要がある。ワークフローの `configure-pages` に `enablement: true` を付けてあるので
自動で設定されることが多いが、権限の都合で失敗する場合は手動で切り替える。

## 実装済みの範囲

マイルストーン M1〜M6 に相当する部分は一通り入っている。

- **M1** 盤面・プッシャー往復・投入・ペイアウト/ロスト判定・手持ちカウンタ・剛体上限
- **M2** 温度／ととのい／体力・帯域テーブル・ゲームオーバー・デバッグパネル
- **M3** 水風呂／フィーバー（採用案A。入水タイミングを賭けるチキンレース）
- **M4** アイテム出現・ロウリュ照準・オロポ
- **M5** サウナ室・蒸気・陽炎・HUD・タイトル／チュートリアル／リザルト・ハイスコア保存
- **M6** 品質オートスケール（30fps を 2 秒下回ったら1段階降格）

仕様 8.3 の追加アイテム（ヴィヒタ／サウナハット／砂時計）は「ゲームとして面白く」の
ブラッシュアップで採用した（後述）。`ItemDef` は効果を `GameContext` 経由で書く形なので、
さらに足すときは `GameContext` にメソッドを 1 つ増やして `ITEM_DEFS` に並べるだけでよい。

## ゲーム性のブラッシュアップ（第2回）

「ゲームとして面白く遊べるように」という依頼で、ヘッドレス実測を回しながら以下を入れた。
計測値は末尾の「検証結果」を参照。

### 1. 盤面の初期山（最重要）

空の盤面から始めていたのが致命的だった。手持ち 30 個を普通のペースで投げると、
山を作るだけで手前に 1 個も落ちないうちに手持ちが尽き、**約 65 秒で餓死（スコア 110）**する。
実機のコインプッシャーが常にコインで満たされているのと同じで、開始時に盤面へ約 70 個を積み
（`BALANCE.field.prefill`）、物理を回して落ち着かせ、さらにプッシャーを 3 周期空回しして
「次の一投で崩れる」定常状態にしてから渡す。タイトル画面の背後でも山が動いている。

これに伴い温度上昇（1.5 → 1.0/個）・ストーン獲得（2 → 1/個）を実機相当に締めた。
落下頻度が 2〜4 個/秒に上がったので、旧値のままだと数秒で灼熱・手持ちは 60 秒で 500 個になる。

### 2. コンボと大玉ストーン

前の落下から 0.4 秒以内に次が落ちると連鎖が伸びる。山が崩れてまとまって落ちる瞬間
（コインプッシャーで一番気持ちいい瞬間）をそのままスコアに変換する。

- スコア倍率: 連鎖 1 段ごとに +0.1（10 連鎖で ×1.9、上限 ×4.0）
- 5 連鎖ごとに手持ちストーン +2
- 10 連鎖ごとに**大玉ストーン**を 1 個獲得（最大 3 個ストック）。次の投入で使われる。
  半径 1.8 倍・質量約 5 倍で山をまとめて押し出し、ペイアウトすると 5 個ぶんの価値

連鎖窓を 1.0 秒にすると投げている間ずっと繋がって 170 連鎖などになり意味を失うので、
散発的な落下（0.5 秒間隔前後）では繋がらない 0.4 秒にした。実測の最大連鎖は 20〜27。

### 3. アイテムを 4 種に

盤面アイテムがオロポだけだったので、仕様 8.3 の案を採用して 4 種にした。
出現間隔も 45 → 32 秒に詰めている。ペイアウト口に落ちたときだけ発動、は変わらず。

| アイテム | 効果 |
|---|---|
| オロポ | 体力 +35、スローモーション |
| ヴィヒタ | 盤面の全ストーンを手前へ一斉に扇ぐ（山崩し。大量落下とコンボの種） |
| サウナハット | 8 秒間、温度帯による体力ダメージを無効化（灼熱に踏み込める） |
| 砂時計 | フィーバー中なら +4 秒延長、それ以外はととのい +40 |

### 4. セット制と難度上昇、放置死

エンドレスなのに終わりが無かった。

- **難度レベル = セット数（手動入水の回数）+ 経過分 × 0.8**。レベルに応じて自然放熱
  （上限 ×2.4）と温度帯ダメージ（上限 ×3.5）が増える (`BALANCE.sets`)
- ととのいボーナスはセット数に比例（1 セット目 250、2 セット目 500 …）
- **冷え帯に体力ダメージ -1.5/s** を入れた（仕様 6.1 の表の変更。仕様 14 章「放置で約 90 秒」の
  受け入れ基準を優先。実測 89〜93 秒）
- **適温は体力 +0.5/s**（同じく表の変更）。「適温を保つ」が中立ではなく能動的な選択になる
- **外気浴中は体力 +2.0/s**。熱い帯で粘って入水するほど外気浴が長く、回復も多い。
  これが無いと攻めた分の体力が戻らず、安全策（MAX 即入水）のほうが常に得だった
- MAX 放置の自動入水は 4 秒の「ぬるい外気浴」だけ。ボーナスなし・セットにも数えない。
  以前は放置で 250 点と 8 秒の無敵が手に入っていた
- 自動入水までの猶予は 8 → 10 秒。点灯してからロウリュで温度を上げる余裕を持たせた
- ロウリュの温度上昇は 1 回最大 +30℃ → +21℃。70℃ から使って熱い帯の上端に収まる値

### 5. HUD と手応え

- ペイアウト口の位置に**スコアが浮かぶ**。0.4 秒以内の連続落下は 1 つの数字に積み上がる
- 画面中央上に**コンボ表示**（連鎖数・倍率・窓の残り）。10 連鎖以上で赤く大きく
- フィーバーバッジに**残り秒数とバー**
- ととのい MAX 中は**自動入水までの残り**を斜線の帯で表示
- スコア横に **SET n**、サウナハット中は「耐熱 n 秒」チップ、体力バーに金縁
- 大玉ストーン所持中は投入レーンが橙に光り「大玉 ×n」バッジ
- 水風呂ボタンは ×2.0 以上で入れるとき熱い色に
- 冷えすぎのときは周縁が青くなる
- リザルトに最大コンボ・最高倍率を追加
- 大玉獲得・大玉ペイアウト・コンボ節目・各アイテムに専用の効果音

### 実装上の注意

- タイトル画面やゲームオーバー中も物理は動くが、そこで落ちた分はスコアにしない
  （`handleSensorHits` の `scoring`）。初期山があるので、この制御が無いとタイトルで点が入る
- 初期山の落ち着かせ (`PhysicsWorld.settle`) はイベントもスコアも出さずに物理だけ回す。
  この間にセンサーへ落ちた分は黙って消す
- 大玉は `TrackedBody.big / value` で表し、描画は InstancedMesh のスケールで済ませている
  （ジオメトリは共有）。剛体上限の間引き対象からは外してある

## フィードバック反映（仕様 v0.1 からの変更）

プレイして頂いた結果を受けて、以下を変更した。

### ロウリュを常設ボタン＋クールタイム制に変更（仕様 8.1 の置き換え）

盤面アイテムとして拾う方式をやめ、水風呂ボタンの右下の常設ボタンにした。

1. ボタンを押すと**ロウリュモード**に入る（もう一度押すと取り消し）
2. モード中は投入レーンが無効になり、盤面をタップすると**水をかける**（着水の輪＋水滴＋蒸気）
3. 水がかかったストーンは**黒く濡れ**、`wetDurationSec` の間 蒸気を上げ続ける
4. **濡れている間だけ室温が上がる**（濡れたストーン数 × `tempPerStonePerSec`、上限あり）
5. 乾くと元の色に戻り、温度上昇も止まる
6. 使用後は `cooldownSec` のクールタイム。ボタンは下から影が引いていく表示になる

かけた瞬間に温度が跳ねる旧仕様（Δtemp = 25 + n×1.5）と違い、**どこにかけて何個濡らせたか**が
そのまま効きの差になる。ロウリュはアイテムから外したので、盤面アイテムは現在オロポのみ。

### 温度ゲージを画面右の縦型温度計に変更（仕様 9章 HUD レイアウトの変更）

上部の横バーから、画面右側の縦ゲージにした。上が高温・下が低温で、帯の色分けは従来どおり。
上部 HUD と下部 HUD の隙間に収まるよう上下を固定してあり、中央基準にはしていない
（中央にすると下部のゲージ群や投入レーンに管が潜り込んで読めなくなる）。

### 修正した不具合

- **コインの落下位置が左右反転していた** — カメラは -Z から +Z を向いているため、
  カメラのローカル +X（画面の右）は world の -X になる。タップ位置をそのまま
  world X に渡していたので左右が入れ替わっていた。`BALANCE.spawn.screenToWorldXSign`
  で符号を合わせている。ロウリュの着弾はレイキャストなので元から正しく、補正は不要。
- **`hidden` 属性が効いていなかった** — UA スタイルの `[hidden] { display: none }` は
  作者スタイルの `display` に負ける。`display` を持つ `.hud` / `.fever-badge` /
  `.cold-bath-btn` / `.aim-overlay` が hidden にしても表示され続けていた
  （フィーバーでないのに ×1.0 バッジが出る、ととのい未満で水風呂ボタンが出る、など）。
  `[hidden] { display: none !important }` で一括修正。

## 仕様からの逸脱（意図的なもの）

実装中に、仕様書の寸法表どおりでは機械として成立しない箇所が 2 つあった。
どちらも「コインプッシャーとして動くこと」を優先して変更している。

### 1. 下段テーブルを Y=0 から下げた

仕様 3 章の寸法表は「プッシャー面 Y=0」「下段テーブル面 Y=0（同一平面）」としているが、
同一平面ではプッシャーが山を押し出せず、ストーンが永久に落ちない。
プッシャー上面は仕様どおり `Y=0` のまま、下段テーブル面のみ `Y=-0.035` へ下げてある
(`BALANCE.field.lowerTableY`)。この段差が「押し出して落とす」中核なので戻さないこと。

### 2. 投入シュートを追加した

仕様には無い固定パーツを 1 つ足している (`BALANCE.field.chute`)。

投入口 (Z=+0.24) からプッシャー板の上へ直接ストーンを落とすと、ストーンは摩擦で
板と一緒に往復するだけで前縁に到達せず、**一度も落ちない**（実測: 120 秒投げ続けて
ペイアウト 0、剛体だけが 390 個まで増加）。実機のコインプッシャーは、コインを板の
前寄りへ配給する経路と、後退する板からコインを掻き落とす固定フードを持っている。

そこで奥から手前へ下る傾斜シュートを 1 枚入れ、この 2 役を兼ねさせた。
投入口・ペイアウト位置・ストローク・周期はすべて仕様どおりのまま、
同じ条件で 120 秒あたり 324 ペイアウトまで改善した。

## 未決事項（仕様 15 章 + 実装中に見つかったもの）

実装を進める上で暫定の値を置いた箇所がある。判断が要るものは以下。

1. **追加アイテムの採否**（仕様 8.3）— ブラッシュアップで 4 種とも採用した。効果は上記。
2. **リトライ導線** — リザルトからの再挑戦のみ実装。コンティニュー要素は入れていない。
3. **スコアの意味づけ** — 「ペイアウト × フィーバー倍率 × コンボ倍率 の加算 + セット数比例の
   ととのいボーナス」に更新。ととのい回数・最大コンボ・最高倍率も別途保持している。
4. **アートテイスト** — 暫定で木目のデフォルメ路線。プリミティブのみで構成。
5. **ステージ複数化** — 未対応。

### 仕様内の矛盾: 「何もしなければ約90秒でゲームオーバー」（解決済み）

仕様 14 章の受け入れ基準 *「何もしなければ約90秒でゲームオーバーになる」* は、
仕様 6.1 の帯域テーブル（冷え帯 ±0）のままでは成立しなかった（実測: 240 秒放置で体力 100）。
ブラッシュアップで **(a) 冷え帯に体力ダメージ -1.5/s** を採用し、実測 89〜93 秒で成立している。
あわせて自動入水を 4 秒の「ぬるい外気浴」（ボーナスなし）にして、放置で無敵時間と点が
手に入る問題も解消した。仕様 6.1 の表からの変更点は冷え帯（±0 → -1.5）と適温（±0 → +0.5）の 2 箇所。

## 検証結果

`?debug=1` のとき `window.__sauna` にテストハーネスが生える。描画を挟まず固定ステップ
だけを回せるので、実フレームレートに縛られずゲーム内時間で挙動を測れる。

ヘッドレス（Chromium + ソフトウェアレンダリング）での実測:

| 項目 | 基準 | 実測 |
|---|---|---|
| 適温維持でととのい MAX | 約12秒 | **12.5秒** |
| 放置でゲームオーバー | 約90秒 | **89〜93秒** |
| 剛体上限 | 120 | 上限内で安定（初期山込みで最大 87） |
| 盤面外へのすり抜け | 無いこと | 10分連続プレイで無し（座標は常に想定範囲内） |
| タブ復帰でゲージが不正変動しない | しないこと | 実時間3秒のポーズを挟んで温度・体力・ととのいとも変化なし |

プレイスタイル別のシナリオ（`?debug=1` の `window.__sauna` を叩くスクリプトで自動操作）:

| シナリオ | 生存 | セット | スコア | 備考 |
|---|---|---|---|---|
| 放置（何もしない） | 93 秒 | 0 | 351 | 初期山が少し崩れる分だけ点が入る |
| 連打のみ（5 投/秒、入水しない） | 327 秒 | 0 | 20,003 | 自動入水 10 回。時間経過の難度上昇で終わる |
| 慎重（2 投/秒、MAX で即入水） | 302 秒 | 14 | 56,584 | 難度 ×3.1 で冷え帯の消耗に耐えられなくなる |
| 攻め（熱い帯で粘り 88℃ 以上で入水、ロウリュ併用） | 74 秒 | 3 | 22,781 | 灼熱に突っ込み過ぎて短命だが毎分の得点は慎重の 1.6 倍 |

改修前の同条件は「連打のみ」が **65 秒で餓死・スコア 110**、「放置」が**死なずに 250 点**だった。
コンボは全シナリオで最大 15〜27 連鎖、大玉ストーンは 5 分のプレイで 50〜70 個がペイアウトしている。

### 未検証の項目

以下は実機でないと確かめられないため、残っている。

- **iPhone SE 世代 Safari で 30fps を下回らないこと** — この環境には GPU が無く、
  ソフトウェアレンダリングでしか動かせないため未検証。M1 最大のリスクとして
  仕様書が挙げている項目なので、実機での確認が必要。
- **初回ロード 3 秒以内** — Rapier の WASM が gzip 後で約 1.1MB あり、
  回線によっては超える可能性がある。
- 実機タッチでの操作感（不感帯 8px の効き、片手・親指のみでの到達性）
- 10 分放置でのすり抜け有無
