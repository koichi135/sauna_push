# サウナ・コインプッシャー

サウナ室を舞台にしたエンドレス型コインプッシャー。コイン＝サウナストーン。
落ちたストーンはストーブに供給され、室温が上がる。プレイヤーは「熱すぎず、ぬるすぎない」
適温を維持しながら *ととのいゲージ* を溜め、水風呂→外気浴（フィーバー）でスコアを稼ぐ。

モバイルブラウザ（縦持ち）向けの 3D ゲーム。全操作シングルタップ。

## 起動

```bash
npm install
npm run dev        # 開発サーバ
npm run build      # 型チェック + 本番ビルド (dist/)
npm run preview    # ビルド結果の確認
npm run typecheck  # 型チェックのみ
```

`?debug=1` を付けて開くと、右上に調整パネルが出る（既定は畳んだ状態。見出しをタップで開閉）。
仕様書 12 章の必須要件で、全バランス値のスライダーと、温度・水風呂・アイテムなどの
強制発火ボタンが入っている。スライダーは `BALANCE` を実行時に書き換えるので、
実機で触りながらそのまま詰められる。

## 公開（GitHub Pages）

`main` への push で `.github/workflows/deploy.yml` が走り、GitHub Pages へ自動デプロイされる。
Actions タブから手動実行（workflow_dispatch）もできる。

公開先: `https://koichi135.github.io/sauna_push/`

`npm run build` は `tsc --noEmit` を含むので、型エラーがあればデプロイ前に落ちる。
Vite の `base` は `'./'`（相対）にしてあり、リポジトリ名のサブパス配下でもそのまま動く。

初回のみ、リポジトリの **Settings > Pages > Source** が **GitHub Actions** になっている
必要がある。ワークフローの `configure-pages` に `enablement: true` を付けてあるので
自動で設定されることが多いが、権限の都合で失敗する場合は手動で切り替える。

## 技術スタック

| 項目 | 採用 |
|---|---|
| 言語 | TypeScript (strict) |
| ビルド | Vite |
| 描画 | Three.js |
| 物理 | Rapier3D (`@dimforge/rapier3d-compat`, WASM) |
| 状態管理 | 自前の有限状態機械 + イベントバス |
| UI | DOM オーバーレイ（3D 内に UI は置かない） |
| 音 | WebAudio 直（手続き生成） |

外部アセットの動的ロードは禁止のため、木目テクスチャ・蒸気スプライト・効果音は
すべて実行時に手続き生成している。バンドル以外に取りに行くものは無い。

## 実装済みの範囲

マイルストーン M1〜M6 に相当する部分は一通り入っている。

- **M1** 盤面・プッシャー往復・投入・ペイアウト/ロスト判定・手持ちカウンタ・剛体上限
- **M2** 温度／ととのい／体力・帯域テーブル・ゲームオーバー・デバッグパネル
- **M3** 水風呂／フィーバー（採用案A。入水タイミングを賭けるチキンレース）
- **M4** アイテム出現・ロウリュ照準・オロポ
- **M5** サウナ室・蒸気・陽炎・HUD・タイトル／チュートリアル／リザルト・ハイスコア保存
- **M6** 品質オートスケール（30fps を 2 秒下回ったら1段階降格）

仕様 8.3 の追加アイテム案（ヴィヒタ／サウナハット／砂時計）は未承認のため実装していない。
`ItemDef` は効果を `GameContext` 経由で書く形にしてあるので、承認され次第
`ITEM_DEFS` に足すだけで拡張できる。

## 仕様からの逸脱（意図的なもの）

実装中に、仕様書の寸法表どおりでは機械として成立しない箇所が 2 つあった。
どちらも「コインプッシャーとして動くこと」を優先して変更している。

### 1. 下段テーブルを Y=0 から下げた

仕様 3 章の寸法表は「プッシャー面 Y=0」「下段テーブル面 Y=0（同一平面）」としているが、
同一平面ではプッシャーが山を押し出せず、ストーンが永久に落ちない。
プッシャー上面は仕様どおり `Y=0` のまま、下段テーブル面のみ `Y=-0.035` へ下げてある
(`BALANCE.field.lowerTableY`)。この段差が「押し出して落とす」中核なので戻さないこと。

### 2. 投入シュートを追加した

仕様には無い固定パーツを 1 つ足している (`BALANCE.field.chute`)。

投入口 (Z=+0.24) からプッシャー板の上へ直接ストーンを落とすと、ストーンは摩擦で
板と一緒に往復するだけで前縁に到達せず、**一度も落ちない**（実測: 120 秒投げ続けて
ペイアウト 0、剛体だけが 390 個まで増加）。実機のコインプッシャーは、コインを板の
前寄りへ配給する経路と、後退する板からコインを掻き落とす固定フードを持っている。

そこで奥から手前へ下る傾斜シュートを 1 枚入れ、この 2 役を兼ねさせた。
投入口・ペイアウト位置・ストローク・周期はすべて仕様どおりのまま、
同じ条件で 120 秒あたり 324 ペイアウトまで改善した。

## 未決事項（仕様 15 章 + 実装中に見つかったもの）

実装を進める上で暫定の値を置いた箇所がある。判断が要るものは以下。

1. **追加アイテムの採否**（仕様 8.3）— 未実装。データ構造だけ拡張可能にしてある。
2. **リトライ導線** — リザルトからの再挑戦のみ実装。コンティニュー要素は入れていない。
3. **スコアの意味づけ** — 暫定で「ペイアウト単純加算 × フィーバー倍率 + ととのい回数ボーナス」。
   ととのい回数も別途保持しているので、そちらを主指標に切り替えることもできる。
4. **アートテイスト** — 暫定で木目のデフォルメ路線。プリミティブのみで構成。
5. **ステージ複数化** — 未対応。

### 仕様内の矛盾: 「何もしなければ約90秒でゲームオーバー」

仕様 14 章の受け入れ基準に *「何もしなければ約90秒でゲームオーバーになる
（温度が下がりきりストーンも尽きる）」* とあるが、**仕様 6 章のルールでは成立しない**。

- 何も投入しなければ手持ちストーンは減らないので `STARVING` にならない
- 温度は下がって「冷え」帯 (0–39) に入るが、この帯の体力変化は仕様 6.1 の表で `±0`
- したがって体力は 100 のまま減らず、放置してもゲームオーバーにならない（実測: 240 秒経過しても体力 100）

現状は**仕様 6.1 の帯域テーブルをそのまま実装**してある。表は
「この関係を壊す変更はしないこと」と明記された中核なので、勝手に冷え帯へダメージを
足すことはしていない。どちらを正とするか判断が必要:

- (a) 冷え帯に小さめの体力ダメージを入れる（放置死が成立する。表の変更）
- (b) 受け入れ基準のほうを実態に合わせる（放置は詰みだが死なない、という設計を認める）

関連して、ととのい MAX 放置による自動入水（仕様 6.2）がこれを増幅している。
自動入水でもフィーバーには入るため無敵時間が発生し、フィーバー明けは温度 5 の
「冷え」帯（＝無害）から始まる。10 分の連続プレイでは 22 回ととのっており、
体感で 3〜5 割が無敵時間になっていた。放置死を成立させる場合は、
自動入水側にも何らかのペナルティ（無敵なし、等）を検討したほうがよい。

## 検証結果

`?debug=1` のとき `window.__sauna` にテストハーネスが生える。描画を挟まず固定ステップ
だけを回せるので、実フレームレートに縛られずゲーム内時間で挙動を測れる。

ヘッドレス（Chromium + ソフトウェアレンダリング）での実測:

| 項目 | 基準 | 実測 |
|---|---|---|
| 適温維持でととのい MAX | 約12秒 | **12.5秒** |
| 熱い帯を維持して体力が尽きる | 約50秒 | 約60〜65秒（途中のフィーバー無敵ぶんを含む） |
| 放置でゲームオーバー | 約90秒 | **成立しない**（上記の矛盾を参照） |
| 剛体上限 | 120 | 上限内で安定（10分連続プレイでの最大 79） |
| 盤面外へのすり抜け | 無いこと | 10分連続プレイで無し（座標は常に想定範囲内） |
| タブ復帰でゲージが不正変動しない | しないこと | 実時間3秒のポーズを挟んで温度・体力・ととのいとも変化なし |
| 通常プレイ 180 秒 | — | ペイアウト 530 / ととのい 6 回 / スコア 6800 |

温度が「投げるほど上がる」ことで、投げ続けると灼熱帯 (95+) に入って体力が削られ、
水風呂でリセットする、というループが実際に回っていることを確認済み。

### 未検証の項目

以下は実機でないと確かめられないため、残っている。

- **iPhone SE 世代 Safari で 30fps を下回らないこと** — この環境には GPU が無く、
  ソフトウェアレンダリングでしか動かせないため未検証。M1 最大のリスクとして
  仕様書が挙げている項目なので、実機での確認が必要。
- **初回ロード 3 秒以内** — Rapier の WASM が gzip 後で約 1.1MB あり、
  回線によっては超える可能性がある。
- 実機タッチでの操作感（不感帯 8px の効き、片手・親指のみでの到達性）
- 10 分放置でのすり抜け有無
